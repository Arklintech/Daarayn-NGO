## 1. What Daarayn is
Daarayn Public Charitable Trust ("Daarayn Foundation") is a charitable-trust operating system built on amanah, transparency, accountability and documentation. It is meant to be one connected system:
- **Public website** collects donations (with payment-proof screenshot) and presents the trust.
- **Admin Panel** (`/admin`) verifies donations, manages donors (CRM), causes, field operations, communications and notifications.
- **Field Agent portal** (`/field`) lets agents file reports with evidence and message Admin.
- **Donor portal** (`/donor`) is a lookup-based donor view.

## 2. Locked architecture (non-negotiable)
| Concern | System |
|---|---|
| Authentication/identity only | Firebase Authentication (client SDK + `firebase-admin` token verification) |
| Structured operational data (sole source of truth) | Google Sheets (`googleapis`, service account) |
| Evidence/files | Google Drive |
| Email | Gmail SMTP via Nodemailer (`EMAIL_PROVIDER=gmail`; Resend adapter exists as an alternative) |
| Realtime | SSE (`/api/realtime/stream`) backed by an append-only `Realtime_Events` sheet tab |
| App | Next.js 16.2.10 App Router, React 19.2.4, TypeScript (strict, `noImplicitAny:false`), Tailwind 4 |
| Hosting | Vercel |
KHIZR / MOMIN / any AI chat or inference must NOT exist. Operational Firestore must NOT exist.

## 3. Application areas (actual)
- Public: `/` (single landing page, mostly static hardcoded sections in `components/LegacySections.tsx`), `/pay` (donation form `components/DonateForm.tsx`), `/donor`, `/donor/dashboard`. There is NO public cause directory, public ledger page, blog, FAQ page or contact page in the App Router. `public/script.js`, `public/pay.html`, `server.js` are legacy static/Express leftovers.
- Admin (`/admin/*`): dashboard, donations, donors (+[id]), causes (+[causeId]), campaigns, programs, communications (+history), notifications, field-ops (+[id]), field-agents (+[agentId]), ledger, beneficiaries, faqs, settings, sync, login. See PROJECT_ROUTE_AND_FEATURE_INVENTORY.md.
- Field (`/field/*`): login, dashboard, reports (list/new/[id]), messages, notifications, profile, help.
- PWA: `app/manifest.ts` (public), `/api/manifest/admin|field` (rewritten from `/admin|field/manifest.webmanifest`), `public/sw.js` network-first with per-scope caches.

## 4. How modules interact (verified in code)
Website donation → `POST /api/donate` → `DonationService.processDonation` → Drive proof upload → donor lookup/create (`Donors`) → `Donations` row with unique `DA###` id (`createWithUniqueId`) → SSE `DONATION_CREATED` → admin `Notifications` row → `Audit_Log` → confirmation email. Admin verifies via `PATCH /api/admin/donations` (status pending/completed/rejected, optimistic `expectedStatus`, audit, SSE). All money figures derive from `lib/donations/metrics.ts` (received = completed/verified/allocated; pending; rejected excluded). Donor ownership of a donation = `donorId` match OR normalized `donorEmail` match.

Field report → `POST /api/field/reports` → Drive (`Field Reports/*`) → `Field_Reports` row → SSE (audience admin + agent) → `Notifications` → `Audit_Log`; Admin PATCH updates status and notifies the agent.

## 6. Current implementation state — headline verified findings
(Full list with severity: PROJECT_KNOWN_ISSUES_AND_NEXT_STEPS.md.)
1. **KHIZR/AI is back**: UI text "Generate with Khizr", and `/api/admin/communications/ai-assist` calls the Anthropic API (and is unauthenticated). Violates the locked decision. Commits `74d4fbf`, `ce14959`, `ccaef78`, `b12b2c6` reintroduced it. `.env.local` still has `GROK_*`, `AI_PROVIDER` variable names.
2. **Unauthenticated PII endpoints**: `/api/donor/lookup` (returns donor profile and auto-creates donors), `/api/donor/dashboard?donorId=`, `/api/media/[fileId]` (serves any Drive file the service account can read, cached public 1 year).
3. **Admin Beneficiaries, FAQs, Settings (admins list, SEO) persist only in browser localStorage** — not shared, not in Sheets.
4. **Email status never persisted on donations**: `DONATION_HEADERS` and `mapEntityToRow` omit `confirmationEmail*` fields, so `donationRepository.update(...)` drops them.
5. **Broadcast history detail is `?id=` on `/admin/communications/history`**; the previously reported path URLs (`/history/BCAST-…`) have no route (the `[id]` page was deleted in `4467ee0`). `npx tsc` reports a type error in the history page (line 28) and a stale `.next/types` reference.
6. **Notification DELETE does not delete** (`BaseRepository.delete` only clears the in-memory cache).
7. `dispatch-updates` counts `emailsSent++` without sending anything.
8. Milestone automations (`/api/admin/communications/automations`) can never match donations (`selectedCauses` is always `[]`).
9. Hidden local-file fallbacks exist (`lib/db.ts` donors/donations JSON, Drive `secure_fallback`, field chat JSON) contrary to "Sheets only".
10. No automated tests exist (no test runner, no test files). "Jest worker" errors in history are Next's internal jest-worker, not a test suite.

## 7. Decisions already made (carry forward)
- Giving totals are derived from donation rows, never from stored donor/cause counters.
- Donation statuses: pending → completed ("Verified" in UI) | rejected.
- Realtime events carry identifiers only; clients re-read via authenticated APIs.
- SMTP acceptance (250 OK) ≠ inbox delivery; the code records "SMTP-accepted".
- Field Agents are "Field Agents" (never "Volunteers").
- Admin authorization = Firebase token email in `ADMIN_EMAILS`; agents = active row in `Field_Agents`.
